# Отчёт о реализации

## Подход к планированию

Используется детерминированный жадный алгоритм:

1. **Топологическая сортировка зависимостей** (алгоритм Кана) с tie-break
   по приоритету (high < medium < low) и порядку поступления.
2. **Жадное размещение**: для каждого рейса находится самая ранняя свободная
   полоса с учётом сепарационных буферов и проверки зависимостей.
3. **Bottleneck-анализ**: DFS по графу зависимостей с мемоизацией находит
   самую длинную цепочку запланированных рейсов.

## Ключевые решения

- **In-memory состояние**: Map-структуры обеспечивают стабильный порядок
  итерации (часть ES2015) и O(1) lookup.
- **Никакого Math.random**: все tie-break детерминированы.
- **Sub-минутная точность**: время в секундах от t=0 (старт планирования),
  без зависимости от Date.now().
- **MCP стек**: @modelcontextprotocol/sdk 1.29 с stdio-транспортом —
  это локальный сервер для Claude Desktop без необходимости HTTP.

## Что сработало

- Чёткое разделение: state.ts (данные), scheduler.ts (логика),
  tools/ + resources/ (адаптеры MCP).
- Zod-валидация ENV даёт мгновенный fail-fast при неверной конфигурации.
- Vitest с InMemoryTransport позволил тестировать MCP-инструменты без
  spawn-процесса.

## Что не сработало

- Изначально пробовали HTTP-транспорт — оказался избыточным для локального
  MVP. Откатились на stdio.
- Поначалу хотели реализовать wake turbulence categories по ICAO Doc 4444 —
  выходит за рамки требований ТЗ. Заменили на простые operationType-буферы.
